## 一、测速口径（必读）

| 项 | 取值 |
|---|---|
| 并发 | **单流**（`--max-num-seqs 1`），无并发 |
| 语料 | deepseek-harness 真实会话报文：1 条 system + 58 个真实工具结果 + 38 个真实工具定义 |
| 采样 | harness 真实值 `temperature=0.7 / top_p=0.8 / top_k=20 / repetition_penalty=1.05` |
| 链路 | 测速机 → 本机转发器 `127.0.0.1:8788` → 模型主机 `:8000`（与线上同一条） |
| 生成长度 | `gen=256`，每档独立一次请求 |
| 配置 | 生产最终配置：W4A16 + DFlash2（probabilistic 草稿采样）+ fp8 KV + 225 W + Marlin atomic add |

### 指标定义与可信度

| 列 | 定义 | 可信度 |
|---|---|---|
| `decode t/s` | `completion_tokens / (total_s − ttft_s)` | **高**，由本请求自身时间戳与 token 数算出 |
| `TTFT` | 首 token 到达时间 | **高**，同上 |
| `prefill t/s` | `prompt_tokens / ttft_s` | 高，但受前缀缓存影响（见下） |
| `drafts` / `acc_rate` / `mean_len` / `pos0..6` | 取自 vLLM 的 **Prometheus 全局计数器**（`vllm:spec_decode_num_*_total`）在请求前后的差值 | ⚠️ **中**：只要测量窗口内有**任何并发流量**（例如同时在用该模型的其他客户端），这些计数就会被别的请求一起算进来，出现 `drafts × mean_len ≫ 256` 的失真 |

> 因此本页把 `decode t/s`、`TTFT`、`prefill t/s` 作为主指标；
> 接受率相关列只在**确认窗口内无并发**的批次里引用（下方单独标注）。

### 前缀缓存的两种口径

同一模板连续打不同档位时，公共前缀会被 vLLM 的前缀缓存命中（`cached` 列），
此时 `TTFT` 只反映**增量 prefill**，不是冷启动。两种口径都会给出：

- **冷启动 TTFT**：缓存为空，第一次请求；
- **热前缀 TTFT**：前缀已在缓存里（连续对话的真实稳态）。

## 三、优化前后 A/B 对照（单变量，同档位同语料）

### 3.1 草稿采样 `greedy` → `probabilistic`（最大收益项）

| 96K | 89.8 | **136.2** | **+52%** | 0.395 | 0.523 |
| 160K | 63.8 | **77.2** | **+21%** | 0.282 | 0.377 |

### 3.2 `VLLM_MARLIN_USE_ATOMIC_ADD=1`

日志：`logs/bench-ea-clean.log`（关闭）/ `logs/bench-base-clean.log`、`logs/bench-marlineadd.log`（开启）

直接比 decode 会被采样随机性干扰，故用与接受率无关的**单步延迟**：
`ms/step = (total_s − ttft_s) × 1000 / drafts`。

| 档位 | 关闭 | 开启 | 单步延迟变化 | 等接受率下 decode 变化 |
|---|---:|---:|---:|---:|
| 32K | 37.8 ms/步 | **36.8 ms/步** | −2.6% | +2.7% |
| 160K | 46.4 ms/步 | **45.0 ms/步** | −3.0% | +3.1% |

### 3.3 功耗墙 225 W → 260 W

日志：`logs/bench-225w.log` / `logs/bench-260w.log`

| 档位 | 225 W | 260 W | 变化 |
|---|---:|---:|---:|
| 32K | 37.5 ms/步 | 37.3 ms/步 | −0.5%（噪声） |

代价：加载态温度 69/57 °C → 80/70 °C，风扇 80%/46%。生产最终锁 **225 W**。

## 四、参考值对照

官方 DFlash2 在 **H200 + 官方 Qwen3.8-27B** 上（`temperature=1.0 / top_p=0.95 / top_k=20`）：
接受长度 4.10（MT-Bench）～5.46（GSM8K），单并发吞吐 **184–236 t/s**。

本机 32K 档接受长度 4.83、第 0 位命中率 **88.7%**；官方公布的第 0 位命中率 **85.4%**。
→ 短上下文下草稿与目标的配对是正常的，差距主要来自**硬件代差**与**长上下文**。
